# Components

`src/components/` contains reusable presentation and interaction. Keep components focused, typed,
and accessible. Put external data access in services and domain-specific business logic in helpers.
Group new components by domain when a child area already exists; use the nearest child instructions
for cards, contact, and layout.

Use Tailwind and DaisyUI. Prefer simple, clean layouts and restrained transitions, hover states,
and micro-interactions when they improve feedback without reducing usability. Review changed
components in the real route at desktop and mobile widths.
